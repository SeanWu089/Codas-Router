# Codas Windows

## 本版的使用目标

Windows 登录后开启 Codas，其他设备上的 Codas 插件可以通过现有 HTTPS 入口，访问这台 PC 明确授权的工作目录。第一次安装和配对完成后，日常使用应只需要开启 Codas；暂时断网、后端启动较慢或进程异常退出，由客户端监护恢复。

本版聚焦 Windows 客户端和安装可靠性。去中心化、核心机自动接替、独立公网入口切换留待后续版本。现有共享入口仍需要正常在线；Windows 睡眠时不要求提供访问。

## 安装与日常运行约定

- 使用固定的用户级安装目录 `%LOCALAPPDATA%\CodasSolStable`，安装后不依赖桌面下载目录、源代码仓库或构建机上的临时依赖目录。
- 安装包携带固定版本的 Node、完整 DevSpace 依赖和需要的 Windows 原生模块。安装阶段不再临时执行 npm 下载依赖。与远端配对和远程使用仍需要网络。
- 用户明确选择允许访问的工作目录。新电脑生成新的安装身份和认证状态；升级保留身份、授权目录和会话序号记录。
- 提供安装目录内的开始、停止和状态入口。停止是明确关闭访问，不会被监护立即重新开启。登录启动遵循已保存的开启状态。
- 本版使用当前用户登录任务，不承诺 Windows 尚未登录时已经提供远程访问。
- 状态区分本地后端可用、远端已配对、连接受阻和文件校验失败。在线心跳不等于远程命令已经执行成功。

安装完整包时，解压外层 ZIP 后运行 `INSTALL.cmd`，按提示选择允许访问的目录；也可显式传入 `-AllowedRoot` 和独立的 `-InstallRoot`。初次配对使用安装目录中的 `PAIR.cmd`，输入现有 HTTPS 入口和配对口令。日常使用安装目录中的 `START.cmd`、`STOP.cmd`、`STATUS.cmd`。配对口令不写入命令行或日志。

安装文件缺失后，从与当前版本校验值匹配的完整包运行 `INSTALL.cmd -Repair`；修复会创建新的版本目录并保留身份、授权目录和损坏证据。选择保留的健康版本时使用 `ROLLBACK.cmd -RetainedVersion <版本目录名>`。本分支中的开发脚本仍须经过成品安装验收。

## 如何处理文件缺失与异常退出

安装前按完整清单核对每个文件，验证成功后才进入版本暂存和切换。每个版本保留自己的依赖和校验清单，持续运行的身份与认证状态放在版本目录之外。切换失败时恢复原版本和本安装拥有的任务定义，不回退已经演进的会话序号。

运行监护先确认后端就绪，再连接远端；暂时不可用时按上限固定的退避继续等待，不因只重试三次而永久退出。依赖缺失或内容变化会留下具体文件及哈希证据。监护不自动覆盖被系统或安全软件处理的文件，不改变安全策略，也不会把未经校验的下载当作修复。损坏需要通过经过验证的完整包恢复。

更新和回退只操作经身份、路径和任务定义核对后确认属于本安装的对象。旧安装和共享依赖必须等迁移验收通过、确认没有进程继续引用后再清理。

## 稳定版必须满足的验收

| 编号 | 使用场景 | 可观察结果 |
| --- | --- | --- |
| WIN-S01 | 干净目录、没有全局 Node/npm、包仓库不可达 | 完整依赖从安装包落地，认证后的本地工作区及命令执行成功 |
| WIN-S02 | 开启 Codas，在另一设备使用 Codas 插件 | 目标 PC 的工作区打开成功，读取及命令返回正确设备的新结果 |
| WIN-S03 | 后端延迟超过三分钟，或本安装的子进程意外退出 | 自动恢复；无需重新配对或重新安装；旧任务不被重复执行 |
| WIN-S04 | 在隔离副本中删除／改动依赖 | 校验拒绝损坏内容，保留证据，原健康版本不被覆盖 |
| WIN-S05 | 准备或切换阶段故障、同名非本产品任务 | 停止前检查所有权；不改无关任务；失败恢复原版本与任务 |
| WIN-S06 | 停止，再开启 Codas | 停止意图被保留；重新开启后以原身份恢复 |
| WIN-S07 | 当前用户登录任务、启动和停止 | 任务归属明确，启动遵循保存意图；实际完整重启和自然唤醒单独记录 |
| WIN-S08 | 固定候选累计唤醒运行（补充观察） | 记录实际观察时长、错误、误执行、干预和恢复时间；无固定时长发布门槛 |
| WIN-S09 | 已验收包迁移到目标 PC | 原身份和授权目录保留，旧版本可回退，实际 Codas 远程执行再次通过 |

自动测试、实际安装验证和用户确认分开记录。完整电脑重启、自然唤醒与其他电脑兼容性只在实际执行后声明已通过。
